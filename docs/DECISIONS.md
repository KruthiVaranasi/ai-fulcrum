# Routing decisions by business use case

Generated by `python -m hybrid.decide` from measured answers of **claude/haiku-nothink** (cheap) and **claude/opus** (frontier). Quality is judged against each use case's bar; costs are equivalent API list prices at ₹88/$. The business inputs are stated assumptions, chosen to be argued with.

**How a strategy is chosen:** among the strategies that meet the use case's quality floor, pick the one with the lowest *expected total cost* = API cost + (share of bad answers × business cost of a bad answer).

| Strategy | How it works |
|---|---|
| Always the cheap model | Every request goes to the cheap model. |
| Always the frontier model | Every request goes to the frontier model. |
| Predict from the prompt, escalate risky ones | A classifier predicts from the prompt alone whether the cheap answer will be bad; escalate when P(bad) × cost of a bad answer ≥ the extra cost. |
| Answer cheaply, verify, escalate failures | The cheap model answers; a cheap check (unit tests for code, a Haiku verifier otherwise) reads the answer; only failures are escalated. |

**Router overhead (measured by `python -m hybrid.overhead`):** the prompt classifier decides in 1.8 ms (median; p95 2.6 ms) on a laptop CPU, at no API cost; the Haiku check adds 4.6 s (median; p95 6.9 s) and about $0.0030 per checked answer; that time is included in the p95 latency below; for comparison, a Haiku *LLM router* would add 4.0 s (median) and $0.0016 per request before any answer is written.

## Internal productivity assistant (rewrites, summaries, emails)

*Employees can see a weak rewrite instantly and just retry. A bad answer costs a few seconds, so cost per request dominates.*

**Inputs:** bar = acceptable · cost of a bad answer = ₹2.00 · floor = 85% · volume = 500,000/month · latency budget p95 = 15 s · n = 40 prompts

| Strategy | Quality | Sent to frontier | Cost / 1k | Expected total / 1k | p95 latency |
|---|---|---|---|---|---|
| Always the cheap model | 82% | 0% | ₹163 | ₹513 | 13 s |
| Always the frontier model | 95% | 100% | ₹997 | ₹1,097 | 17 s |
| Predict from the prompt, escalate risky ones | 85% | 32% | ₹468 | ₹768 | 17 s |
| Answer cheaply, verify, escalate failures ✅ | 88% | 12% | ₹422 | ₹672 | 23 s |

- **Decision:** Answer cheaply, verify, escalate failures → 88% quality at ₹422/1k; about ₹211,134/month vs ₹498,269 all-frontier.
- **The check itself:** caught 29% of bad cheap answers; escalated 9% of answers that were actually fine. Checking each answer on its own call (no batching, as an interactive product would) raises this strategy to ₹620/1k, a 38% saving vs all-frontier.
- **Latency:** ⚠️ the recommended strategy's p95 is 23 s, over the 15 s budget.
- **Threshold intuition:** with prompt-based routing, most traffic moves to the frontier model once a bad answer costs about ₹6.31 or more.
- **Robustness:** changes when quality floor −5 pts → Always the cheap model; quality floor +5 pts → Always the frontier model.
